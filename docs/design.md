# WindowTint 0.4.15 设计

## 目标

把本地图片处理成柔和、低对比度的透明层，并通过进程内注入显示在普通 Windows 11
桌面窗口中。整窗透明层由目标窗口的原生移动消息驱动，不修改标题栏、边框或文字颜色。

## 组件

- `artwork.py`：按窗口比例等比铺满原图，并生成自上而下渐隐的白色柔焦层。
- `theme.py`：从整图与边缘区域取色，生成标题栏、边框和强调色。
- `native.py`：枚举顶层窗口，缓存每个 PID 的路径、位数、令牌和反作弊模块检查；只调整窗口圆角。
  资源管理器文件窗口标记为 `external`，不进入进程注入路径。
- `injection.py`：远程载入 64 位 `WindowTintInjector.dll`，调用应用和移除导出。
- `native/injector/WindowTintInjector.cpp`：在目标进程内替换并还原窗口过程，创建和管理整窗透明层。
- `session.py`：记录本次会话真正应用过的 HWND，并保留每个目标使用的 `injected`/`external` 渲染方式。
- `workflow.py`：计算常驻监视中的新增与已关闭窗口。
- `tray.py`：托盘菜单和后台生命周期。
- `single_instance.py`：使用本机命名互斥量识别重复启动，并恢复已有设置窗口。
- `app.py`：浅色设置界面、图片预览、自定义抗锯齿控件、透明度/柔化、范围选择、常驻开关和状态反馈。
- `advanced.py`：只读检测 SecureUxTheme 的安装状态。

`overlay.py` 是资源管理器专用的外部覆盖层，不向 `explorer.exe` 注入代码。

对标准 Win32 窗口和系统对话框，注入器使用绘制钩子模式：在 `WM_ERASEBKGND` 阶段把
背景图画到窗口客户区，随后应用仍按自己的流程绘制文字和控件。该模式由窗口类白名单
（如 `#32770`、`Notepad`、`WordPadClass`）选择；Chromium、Tauri 等自绘框架不会被误判。
绘制钩子模式的背景图不叠加工作区雾面，并按默认柔化与浓度的约一半处理，让底层图片干净
地显示，文字和控件保持清晰。

## 数据流

```text
图片
  -> Pillow 柔化与 Alpha 合成
  -> 本地版本化 PNG
  -> 安全窗口枚举
  -> 设置窗口圆角，不改原生标题栏/边框颜色
  -> 普通窗口：向目标进程载入带版本号的 WindowTintInjector DLL
  -> 普通窗口：替换顶层窗口过程并创建进程内透明层
  -> 资源管理器：由 WindowTint 自己创建外部透明层
   -> WinEvent 位置事件即时同步外部层
   -> 前台窗口以 8 毫秒间隔主动校准外部层
   -> 100 毫秒轮询兜底后台可见状态与遗漏事件
  -> UpdateLayeredWindow 显示背景
```

拖动和移动只调用 `SetWindowPos` 更新透明层位置，不重新缩放、不重新上传位图。注入层在
`WM_MOVING` 中按系统给出的下一窗口矩形预移动，随后由 `WM_MOVE` 校准，因此拖动期间不会
隐藏或等待松手。资源管理器外部层由 `EVENT_OBJECT_LOCATIONCHANGE` 事件驱动，目标位于前台
时同时以 8 毫秒间隔主动读取边界；后台只保留 100 毫秒兜底轮询。窗口进入连续缩放时仍会
暂时隐藏透明层并停止重绘；尺寸稳定 120 毫秒或原生缩放结束后，再按最终尺寸上传一次。

背景图按每个目标窗口的真实尺寸生成，并通过居中裁切铺满整个窗口。图片主体不会拉伸，
也不再使用上下模糊补边，因此不会出现明显的横向分隔。默认浓度保持为 40%、柔化 4 px。

顶部白色柔焦使用连续纵向渐变：顶部覆盖最强，向下平滑衰减，底部只保留较低透明度。
蒙版在横向上完全一致，不再依赖径向轮廓，因此不同图片和窗口比例都不会产生弧形色带。
关闭“顶部白色柔焦”后改为整窗统一柔化，并立即刷新已经应用的窗口。

超大窗口的背景先在最长边 1920 的中间尺寸上完成柔化和合成，再交给注入器或外部层做高质量
缩放，避免连续缩放时反复对整张 4K 位图做高斯模糊。普通注入窗口在尺寸稳定约 400 毫秒后
才重渲染一次；资源管理器外部层由自身的位置事件负责尺寸跟随，不进入这条重渲染队列。

窗口最大化、还原或拖动改变尺寸后，控制进程会观察目标窗口外框。尺寸连续变化期间不提交
新位图；尺寸稳定约 180 毫秒后，后台线程按最终尺寸重新渲染背景，再通过现有注入或外部层
接口替换旧图。这样避免把初始小窗口的背景直接放大造成发糊，也能让纵向柔焦继续适配
新窗口高度。渲染队列只在后台运行，不阻塞 Tk 主线程；替换完成后会清理上一张运行时位图。

## 安全设计

- 不应用到系统、安全软件、反作弊、AppContainer、提权或 32 位进程。
- 不向 `explorer.exe` 注入；只处理文件资源管理器窗口，桌面、任务栏和 Shell 系统窗口不进入列表。
- 任何令牌、模块或进程信息读取失败都按拒绝处理。
- 只记录实际应用成功的 HWND，恢复时不扫描或重置未触碰窗口。
- 注入 DLL 使用固定的本地路径，不联网下载。
- 注入前扫描目标进程模块；存在其他版本注入器时拒绝叠加，并要求重启目标程序。
- 透明图片层鼠标穿透且不激活，不读取目标窗口内容。
- 恢复时销毁透明图片层并还原原窗口过程，但 DLL 保留到目标进程退出。

## 已知限制

- 注入和远程线程可能被安全软件拦截或告警。
- 注入代码兼容性问题可能影响目标进程稳定性。
- 图片层位于目标窗口内容上方，并非所有软件都存在可独立替换的原生背景层。
- 资源管理器外部层在特殊 z-order、系统动画或跨桌面切换时可能短暂错位。
- 外部层与 Explorer 属于不同顶层窗口，无法保证 DWM 同帧合成；完全无缝需要注入 Shell，
  当前版本不采用该方案。
- 第三方软件若使用独占全屏、受保护视频或特殊硬件覆盖层，图片层可能显示异常。
- 受保护窗口、安全桌面和独占全屏不处理。
- 覆盖层是视觉合成方案，不是修改软件原生主题资源。

## 测试

- 单元测试覆盖图片柔化、Alpha 上限、安全筛选、DWM 回滚、会话恢复、注入调用和常驻监视计划。
- `tests/injection_smoke.py` 使用真实 Tk 目标进程连续应用三次，验证 DLL 载入、每窗口只保留
  一个整窗透明层、截图变化与恢复。
- `tests/watchdog_smoke.py` 验证控制进程被结束后，透明层会由目标进程内的监视线程清理。
- `tests/resize_motion_smoke.py` 验证连续缩放和真实拖动缩放期间不会同步重绘，并检查最终
  透明层恢复、尺寸与延迟。
- `tests/maximize_refresh_smoke.py` 将真实注入目标最大化，验证最终背景位图尺寸与最大化窗口
  外框完全一致，等待异步图片替换实际上屏后截图，并确认透明层仍正常覆盖。
- `tests/app_resize_smoke.py` 对真实注入目标连续快速缩放，验证尺寸稳定后只生成一张最终背景，
  不会在拖动期间反复重渲染。
- `tests/move_tracking_smoke.py` 验证真实拖动期间注入层和资源管理器外部层持续可见，
  逐帧位置误差不超过 3 px。
- `tests/explorer_overlay_smoke.py` 验证真实文件资源管理器窗口能进入列表、通过界面应用、
  跟随移动并完整恢复，同时不注入 `explorer.exe`。
- `tests/resident_smoke.py` 检查托盘运行期间应用状态与恢复行为。
- `tests/single_instance_smoke.py` 验证关闭到托盘后重复启动只会恢复现有窗口，第二个进程退出。
- `tests/ui_smoke.py` 生成界面截图，检查预览、自绘控件、中文化选项和文本布局。
